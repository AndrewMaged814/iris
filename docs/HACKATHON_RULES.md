## Judging

The homepage's expanded judging FAQ names four criteria and says scores depend on measurable
business impact; judging happens online. [Official judging guidance](https://ai.untap.us/#faq).

| Published criterion | Published meaning |
| --- | --- |
| Does it work? | A functioning live agent; the homepage specifies that a judge can run it end to end. |
| Time saved | Hours returned to the SME; the homepage frames this per week. |
| Cost saved | Spending the SME no longer needs. |
| Revenue generated | New income the agent helps create. |

**Not found in the inspected public pages:** percentage weights, a scoring formula,
minimum sample size, required pilot duration, a prescribed measurement method, or a separate
innovation criterion. This does not prove none exist in private participant guidance.
The pages do not clearly say every entry must demonstrate all three kinds of economic impact.

## Required artifacts and submission route

All three artifacts are marked required on the
[program page](https://ai.untap.us/programs/aaw-1st-edition):

| Artifact | Confirmed requirement |
| --- | --- |
| GitHub repository | Working agent and source, with a README enabling a judge to run it in **under five minutes**. |
| Impact slides | A short deck identifying the SME, the workflow replaced, and **measured business impact**. |
| Demo video | **2–3 minutes** showing the agent doing its job. |

The [walkthrough](https://ai.untap.us/how-to-submit) directs participants to log in with
their registered account, open the program's submission round, supply a GitHub link,
upload slides, and attach a video file or link as requested by the form. Submission goes
through the program, rather than email. File limits, accepted slide formats, video-hosting
rules, repository visibility, access credentials, and final form fields were not verified.

For Iris, judge access is a practical consequence of the runnable-agent criterion, not a
published instruction to make the owner profile public. Document and test a judge's access
route while retaining the owner-only Telegram controls. A timed setup/run and actual
merchant workflow comparison are useful evidence; simulations, projected savings, and
owner-reported outcomes need clear labels. The organizer asks for measured impact, and
the repository's [current status](STATUS.md) currently reports no verified merchant outcome.

proactive recommendations already exist. A credible Iris claim is the demonstrated experience:
selected outside-market evidence → equivalent-product/offer comparison → this owner's costs
and stock → a sourced decision in Telegram → remembered review. This remains a workflow
hypothesis, not proof of uniqueness or measured economic value. No new feature follows from
this prior-art check alone.
